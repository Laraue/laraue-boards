Issue можно передать ИИ-агенту для разработки — Claude Code или OpenAI Codex на вашем компьютере, с вашими репозиториями и вашими настройками. Агент берёт issue, работает над ним, пишет о ходе работы в комментариях и переводит issue на проверку.

## Как это работает

1. **Вы передаёте issue.** В блоке **Агент** на странице issue нажмите **Передать агенту**. На карточке на доске появится **Для агента**.
2. **Агент его берёт.** Раннер на вашем компьютере — [laraue-boards-agent](https://github.com/Laraue/boards-agent) (коротко `lba`), см. [ниже](#настройка-раннера) — входит с вашим [API-ключом](/ru/documentation/integrations/api-keys), забирает переданные вам issues, работает в репозиториях пространства в ветке с номером issue и переводит issue в работу. На карточке — **Агент работает**.
3. **Агент работает.** Пишет комментарии о ходе работы и итог, затем переводит issue в статус проверки. На карточке — **Агент готов · проверьте**, а компьютер показывает уведомление.
4. **Вы проверяете.** Переведите issue в «готово» или попросите доработку: [прямо на своём компьютере](#как-попросить-доработку) командой `lba continue` или кнопкой **Вернуть агенту** в блоке «Агент».

Если issue хоть раз передавали агенту, значок остаётся на карточке: после проверки — **Сделано агентом**, если запуск отменили — **Агент отменён**. Если агент не справился, на карточке будет **Агент не справился**; на странице issue причина и время показаны в красной рамке в блоке «Агент», а раннер оставляет комментарий с подробностями. Если потом вы доделаете issue сами, значок станет серым: **Сделано без агента**.

## Кто может передать issue

Только исполнитель issue и только своему агенту: раннер работает лишь с issues, назначенными пользователю, чей API-ключ он использует. Никто другой не может отправить работу на ваш компьютер.

Кнопка **Передать агенту** неактивна (причина видна в подсказке), пока:

- у вас нет [API-ключа](/ru/documentation/integrations/api-keys) в организации — раннер входит с ним, а настройка раннера его создаёт,
- issue не в статусе категории «Не начато», или
- на его доске нет статусов для каждого этапа, через который проходит агент: «Не начато», «В работе», «На проверке».

## Пока issue у агента

Issue **нельзя изменить**: нельзя менять заголовок, описание, атрибуты, вложения и исполнителя, нельзя удалить issue — агент работает с тем, что вы ему передали. Статус и комментарии менять можно. Комментарии не от исполнителя агент воспринимает как информацию, а не как указания.

Любой, кто может редактировать issue, может отменить запуск крестиком **×** рядом с его значком в блоке «Агент». Это останавливает агента и снимает блокировку.

## Заблокированные issues

Можно передать агенту [заблокированный issue](/ru/documentation/features/issue-links). Он будет ждать — агент не возьмёт его, — пока все блокирующие issues не будут готовы.

## Настройка раннера

[laraue-boards-agent](https://github.com/Laraue/boards-agent) (коротко — `lba`) — это раннер: одна программа для macOS, Windows и Linux, которая работает на вашем компьютере. Сейчас он в бета-версии. Нужны git и агент для разработки — [Claude Code](https://claude.com/claude-code) или [Codex](https://developers.openai.com/codex/cli).

Раннер устанавливается одной командой — она скачивает последний релиз и запускает настройку:

```bash
curl -fsSL https://raw.githubusercontent.com/Laraue/boards-agent/main/install.sh | sh
```

В Windows — в PowerShell:

```powershell
irm https://raw.githubusercontent.com/Laraue/boards-agent/main/install.ps1 | iex
```

Во время настройки раннер:

1. Выбирает агента: тот, что у вас установлен, а если установлены оба — спрашивает.
2. Открывает Boards в браузере. Проверьте, что код на странице совпадает с кодом в терминале, выберите организацию и нажмите **Разрешить**. Boards создаст [API-ключ](/ru/documentation/integrations/api-keys) с названием агента и вашего компьютера, например «Claude Code agent (MacBook)», а раннер сохранит его в «Связке ключей» или «Диспетчере учётных данных» — копировать ключ никуда не нужно.
3. Спрашивает, в какой папке лежат копии ваших репозиториев (путь можно ввести или выбрать папку в Finder или Проводнике), и показывает, какие репозитории нашлись для каждого пространства ([см. ниже](#в-каких-репозиториях-работает-агент)).
4. Спрашивает, [где работать агенту](#где-работает-агент).
5. Спрашивает, что делать с веткой агента, когда он закончит: ничего, запушить или запушить и открыть пул-реквест ([см. ниже](#когда-агент-закончил)).
6. Предлагает запускать раннер в фоне, в том числе после перезагрузки, — тогда ничего не придётся запускать вручную.

Чтобы обновиться, ещё раз выполните команду установки: она заменит laraue-boards-agent и перезапустит его, не задавая вопросов заново. Изменить ответы можно командой `lba setup`. Подробности — в [README](https://github.com/Laraue/boards-agent#readme).

## В каких репозиториях работает агент

Репозитории пространства — это его [ссылки](/ru/documentation/concepts/spaces#описание-и-ссылки), URL которых совпадает с git remote репозитория, склонированного на ваш компьютер. Добавьте URL репозитория в ссылки пространства — и раннер сам найдёт вашу копию: ничего сопоставлять не нужно, а ссылка, добавленная позже, учитывается со следующей передачи issue. Добавляйте только те репозитории, в которых делаются issues этого пространства: каждый из них, если он склонирован на ваш компьютер, участвует в каждом запуске.

У пространства может быть несколько репозиториев — например, бэкенд и веб-приложение. Агент меняет только те, что нужны для issue, — в каждом в ветке с одним и тем же именем. Описание пространства и остальные его ссылки (документацию, макеты) агент получает как контекст, а не как указания.

Если на этом компьютере нет ни одного репозитория пространства, issue ждёт другой ваш компьютер, где они есть.

## Где работает агент

Во время настройки раннер спрашивает, какой из двух вариантов вам удобнее:

- **Отдельный worktree на каждый issue** (по умолчанию). Агент работает в своей копии каждого репозитория, в ветке с номером issue, например `agent/WEB-42-fix-export`. Ваши копии остаются как есть, и вы можете тем временем работать в них.
- **Ваши собственные копии, по одному issue за раз.** Раннер обновляет основную ветку каждого репозитория и переключает вашу копию на новую ветку от неё. Когда агент закончит, копия так и останется на этой ветке: откройте её в редакторе, запустите приложение и проверяйте как обычно. Копии, которые агент не менял, возвращаются на ту ветку, где были.

  Чистую копию раннер переключает без вопросов, на какой бы ветке она ни была — например, на ветке прошлого issue, который вы ещё проверяете; её коммиты остаются в той ветке. Раннер спрашивает (в диалоговом окне) только о копиях с незакоммиченными изменениями: при переключении они могли бы перенестись в новую ветку или вызвать конфликт. Кнопка **Continue** запускает проверку заново: ваши незакоммиченные изменения раннер никогда не трогает, поэтому спрашивает снова, пока вы их не закоммитите или не уберёте в stash. **Not now** откладывает issue — раннер спросит ещё раз через 10 минут.

В обоих случаях агент работает с фиксированным списком разрешённых команд и не может пушить.

## Когда агент закончил

- **Уведомления.** Компьютер показывает уведомление от **laraue-boards-agent** с логотипом Laraue: когда агент начинает работу, когда issue готов к проверке, когда агент не справился и когда запуск отменён. Нажмите на уведомление, чтобы открыть issue. При первом уведомлении macOS может спросить, разрешить ли laraue-boards-agent их присылать.
- **Ветка.** По умолчанию она остаётся на вашем компьютере — вы проверяете её и пушите сами. Если вы выбрали это при настройке, laraue-boards-agent сам запушит её после того, как агент закончит, — в каждом репозитории, который агент менял, — и может открыть пул-реквест, если установлен и авторизован [GitHub CLI](https://cli.github.com). Ссылки будут в комментарии laraue-boards-agent к issue и в уведомлении. Сам агент никогда не пушит.

## Как попросить доработку

**На своём компьютере: `lba continue`.** Работа агента лежит у вас на компьютере, поэтому доработку быстрее всего попросить прямо там. Выполните в терминале:

```bash
lba continue
```

Откроется та же сессия агента, в которой он работал над issue, — тот же разговор со всем, что он знал, в тех же репозиториях и в ветке issue. Если не указать номер issue, берётся issue той ветки, на которой вы сейчас, а если такого нет — последний issue, над которым работал ваш агент; команда напишет, какой issue выбрала. Напишите, что не так («кнопка всё ещё синяя», «добавь тест для пустого списка»): изменения сразу видны, приложение можно тут же запустить. В Boards при этом ничего не меняется, и ждать раннер не нужно. Когда вы выйдете из сессии, к issue добавится один комментарий с новыми коммитами.

Чтобы поручить одну правку, не продолжая разговор, напишите её сразу после команды (кавычки не нужны). Агент сделает её сам и выведет ответ в терминал:

```bash
lba continue WEB-42 сделай кнопку красной, как остальные основные кнопки
lba continue WEB-42 выведи JSON дашборда Grafana для новых метрик
```

Сессия есть только на том компьютере, где агент работал над issue. В режиме собственных копий раннер сначала переключит ваши копии обратно на ветку issue и спросит вас только о незакоммиченных изменениях.

**Из Boards: «Вернуть агенту».** Если issue на проверке, нажмите в блоке «Агент» **Вернуть агенту** и напишите, что не так: комментарий добавится к issue, issue вернётся в статус «Не начато» и снова уйдёт агенту. Агент продолжит в той же ветке — в его комментарии будет «continuing … (N commits so far)». Это удобно, когда вас нет за компьютером.

## Для авторов раннеров

Раннер использует MCP-инструменты: `list_agent_runs` (опрос с `state: Ready`, вашим id из `get_me` в `assigneeIds` и `excludeBlocked: true`), `claim_agent_run` (true — issue ваш, false — пропустить), `finish_agent_run` (`Done` или `Failed` с причиной), `get_issue`, где `latestAgentRun` показывает, не отменён ли запуск, и `get_space` — описание и ссылки пространства. Каждое изменение запуска видно в [истории изменений](/ru/documentation/features/issue-history) issue вместе с API-ключом, который его сделал.
