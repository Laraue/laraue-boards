У Laraue Boards есть удалённый **MCP**-сервер (Model Context Protocol), поэтому ИИ-агент вроде Claude может работать с вашими issues напрямую — просматривать их, открывать нужный issue, переводить его в другой статус или оставлять комментарий, — и ничего не придётся копировать вручную.

## Что понадобится

Учётная запись в Laraue Boards. Claude и Claude Code входят в Boards при подключении: Boards спрашивает, в какой организации им работать, и вы даёте разрешение. Другие клиенты, например Cursor, подключаются по [API-ключу](/ru/documentation/integrations/api-keys) — создайте его перед подключением: **Профиль в организации → API-ключи**.

## Подключение в Claude

В Claude введите `/mcp`, чтобы открыть список MCP-коннекторов, выберите добавление собственного коннектора (**custom connector**) и укажите URL:

- **URL**: `https://boards.laraue.com/boards-mcp/mcp`

При подключении Claude откроет Boards: войдите, если ещё не вошли, выберите организацию и нажмите **Разрешить**. После этого вы вернётесь в Claude, и коннектор будет готов к работе.

Если удобнее API-ключ, вместо входа добавьте к коннектору заголовок:

- **Заголовок**: `X-Api-Key` со значением вашего API-ключа

![Добавление MCP-коннектора Laraue Boards в Claude: URL сервера и заголовок X-Api-Key](https://laraue.com/static/images/blog/docs/laraue-boards/claude-mcp-connector-setup.jpg)

Laraue Boards опубликован и в [официальном реестре MCP](https://registry.modelcontextprotocol.io) под именем `com.laraue/boards`, поэтому его найдёт любой MCP-совместимый клиент, который умеет искать в реестре.

## Подключение Claude Code

Выполните один раз в терминале:

```bash
claude mcp add --transport http boards https://boards.laraue.com/boards-mcp/mcp
```

Затем введите `/mcp` внутри Claude Code, выберите `boards` и пройдите аутентификацию: в браузере откроется Boards, где нужно выбрать организацию и нажать **Разрешить**.

По умолчанию сервер добавляется только для текущего проекта. Добавьте `--scope user`, чтобы он был доступен во всех проектах.

Чтобы подключиться по API-ключу, передайте его в заголовке:

```bash
claude mcp add --transport http boards https://boards.laraue.com/boards-mcp/mcp \
  --header "X-Api-Key: ВАШ_API_КЛЮЧ"
```

С `--scope project` сервер попадёт в `.mcp.json` проекта вместе с ключом — не коммитьте этот файл в репозиторий.

## Подключение Cursor

Добавьте сервер в `.cursor/mcp.json` проекта или в `~/.cursor/mcp.json` для всех проектов:

```json
{
  "mcpServers": {
    "boards": {
      "url": "https://boards.laraue.com/boards-mcp/mcp",
      "headers": {
        "X-Api-Key": "${env:BOARDS_API_KEY}"
      }
    }
  }
}
```

Задайте `BOARDS_API_KEY` в переменных окружения вашей оболочки, чтобы ключ не лежал в файле.

## Подключение нескольких организаций

Одно подключение работает с одной организацией. Чтобы агент работал, например, и с личной организацией, и с организацией компании, добавьте сервер дважды под разными именами и при каждом входе выберите свою организацию:

```bash
claude mcp add --transport http boards-personal https://boards.laraue.com/boards-mcp/mcp
claude mcp add --transport http boards-work https://boards.laraue.com/boards-mcp/mcp
```

Пройдите аутентификацию для каждого из них через `/mcp`. Агент видит оба сервера с их инструментами, и ему можно указать, с каким работать («в boards-work создай issue…»). В Claude так же добавьте второй собственный коннектор с другим именем. При подключении по API-ключам укажите для каждого подключения ключ его организации.

Что можно попросить агента после подключения, рассказано в статье [Бэклог для разработки с ИИ](/ru/documentation/use-cases/ai-agent-backlog).

## Что умеет Claude

Каждое действие выполняется с вашими правами и сразу: Claude не может сделать в организации ничего, чего не могли бы вы сами, и вообще ничего не может, если API-ключ его подключения отозван.

- **Issues** — просматривать и фильтровать issues, открывать issue целиком, создавать новый (с заголовком), менять заголовок, описание или исполнителя, переводить в другой статус (сохраняя или удаляя значения атрибутов, которые новая доска не использует) и удалять
- **Комментарии** — добавлять комментарии к issues и редактировать свои, в том числе с файлами (например, отчётом или конфигом)
- **Структура организации** — смотреть пространства (с их [описанием и ссылками](/ru/documentation/concepts/spaces#описание-и-ссылки)), статусы, атрибуты (все или только те, что использует доска) и участников, чтобы Claude сам находил id по названиям
- **Вложения** — прикреплять изображения и документы к issues и комментариям и читать их: изображение — как изображение, Markdown, TXT и JSON — как текст, PDF и Word — как файл; форматы и ограничения — в статье [Вложения](/ru/documentation/features/media#что-можно-прикрепить)
- **Связи issues** — связывать issues (блокирует, связан с, дублирует), удалять связи и пропускать заблокированные issues, когда агент ищет, за что взяться, — см. [Связи issues](/ru/documentation/features/issue-links)
- **Запуски агента** — передавать issue своему агенту для разработки, а раннеру — забирать и завершать переданные вам issues, — см. [Передача issues ИИ-агенту](/ru/documentation/integrations/agent-hand-off)

Claude предлагает только те действия, которые вам действительно разрешены, — например, не предложит удалить issue в пространстве, где у вас нет права на удаление.

## Отзыв доступа

Каждое подключение работает через API-ключ: созданный вами или тот, что Boards создал при входе клиента, — он называется по имени клиента, например `Claude (claude.ai)` или `Claude Code (claude.ai)`. Отзовите ключ в любой момент в разделе **Профиль в организации → API-ключи** — и агент сразу потеряет доступ к этой организации, как и при отзыве любого другого ключа.
