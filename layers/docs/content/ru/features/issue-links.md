Связь соединяет два issues одной организации и показывает, как они относятся друг к другу. Связи перечислены в блоке **Связи** на странице issue и сгруппированы по тому, что они значат для этого issue.

## Типы связей

- **Блокирует / Заблокирована** — один issue нужно сделать раньше другого. Если ISS-3 блокирует ISS-7, то у ISS-7 он будет в группе **Заблокирована**, а у ISS-3 issue ISS-7 будет в группе **Блокирует**. Связи «блокирует» не могут замыкаться в круг.
- **Связана с** — issues связаны, но без порядка. С обеих сторон связь выглядит одинаково.
- **Дублирует / Дублируется** — один issue повторяет другой. Issue с пометкой **Дублирует** — копия, второй — оригинал.

Между двумя issues может быть только одна связь. Чтобы поменять её тип, удалите связь и добавьте новую.

## Добавление и удаление

На странице issue нажмите **Добавить связь**, выберите тип связи и введите номер другого issue или слова из его заголовка. Связь сохраняется сразу — нажимать **Сохранить изменения** не нужно. Чтобы удалить связь, наведите на неё курсор и нажмите кнопку удаления.

Нужно право редактировать issue, к которому вы добавляете связь, и доступ ко второму issue. Связи с issues, которые вам не видны, не показываются.

Добавление и удаление связи попадает в [историю изменений](/ru/documentation/features/issue-history) обоих issues.

## Заблокированные issues

Issue **заблокирован**, пока блокирующий его issue не завершён — то есть находится в статусе категории «Не начато», «В работе» или «На проверке». Блокировку снимает только категория «Готово».

На карточке заблокированного issue на доске стоит отметка **Заблокирована**. Issue, переданный [агенту](/ru/documentation/integrations/agent-hand-off), ждёт, пока он заблокирован, и агент берётся за него, когда все блокирующие issues готовы.

ИИ-агенты, подключённые [по MCP](/ru/documentation/integrations/mcp), видят те же связи у каждого issue и могут пропускать заблокированные issues, когда ищут, за что взяться.
