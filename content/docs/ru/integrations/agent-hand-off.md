Задачу можно передать AI-агенту для кода — Claude Code или OpenAI Codex на вашем компьютере, с вашими репозиториями и вашими настройками. Агент берёт задачу, работает над ней, пишет о ходе работы в комментариях и переводит её на проверку.

## Как это работает

1. **Вы передаёте задачу.** В разделе **Агент** на странице задачи нажмите **Передать агенту**. На карточке на доске появится **Для агента**.
2. **Агент её берёт.** Раннер на вашем компьютере — [laraue-boards-agent](https://github.com/Laraue/boards-agent) (коротко `lba`), см. [ниже](#настройка-раннера) — входит с вашим [API-ключом](/ru/documentation/integrations/api-keys), забирает переданные вам задачи, ведёт работу на ветке с именем задачи в репозиториях спейса и переводит задачу в работу. На карточке — **Агент работает**.
3. **Агент работает.** Пишет комментарии о ходе работы и итог, затем переводит задачу в статус проверки. На карточке — **Агент готов · проверьте**, а компьютер показывает уведомление.
4. **Вы проверяете.** Переведите задачу в «готово» или попросите изменений: [прямо на своём компьютере](#как-попросить-изменений) командой `lba continue` или кнопкой **Вернуть агенту** в разделе «Агент».

Значок остаётся на карточке, если задачу хоть раз передавали агенту: после проверки — **Сделано агентом**, у отменённого запуска — **Агент отменён**. Если агент не справился, на карточке будет **Агент не справился**. На странице задачи причина и время — в красной рамке в разделе «Агент», а раннер оставляет комментарий с подробностями.

## Кто может передать задачу

Только исполнитель задачи и только своему агенту: раннер работает лишь с задачами, назначенными пользователю, чей API-ключ он использует. Никто другой не может отправить работу на ваш компьютер.

Кнопка **Передать агенту** неактивна, а причина видна в подсказке, пока:

- у вас нет [API-ключа](/ru/documentation/integrations/api-keys) в организации — раннер входит с ним, а настройка раннера его создаёт,
- задача не в не начатом статусе, или
- на её доске нет статусов для каждого этапа, через который проходит агент: не начато, в работе, на проверке.

## Пока задача у агента

Задача **заблокирована для изменений**: нельзя менять заголовок, описание, атрибуты, вложения и исполнителя, нельзя удалить задачу — агент работает с тем, что вы передали. Статус и комментарии менять можно. Комментарии не от исполнителя агент воспринимает как информацию, а не как указания.

Любой, кто может редактировать задачу, может отменить запуск крестиком **×** рядом с его значком в разделе «Агент». Это останавливает агента и снимает блокировку.

## Заблокированные задачи

Можно передать [заблокированную задачу](/ru/documentation/features/issue-links). Она ждёт — агент её не берёт, — пока все блокирующие задачи не будут готовы.

## Настройка раннера

[laraue-boards-agent](https://github.com/Laraue/boards-agent) — коротко `lba` — это раннер: одна программа на вашем компьютере, для macOS, Windows и Linux. Сейчас он в бета-версии. Нужны git и агент для кода — [Claude Code](https://claude.com/claude-code) или [Codex](https://developers.openai.com/codex/cli).

Установите его одной командой — она скачивает последний релиз и запускает настройку:

```bash
curl -fsSL https://raw.githubusercontent.com/Laraue/boards-agent/main/install.sh | sh
```

В Windows, в PowerShell:

```powershell
irm https://raw.githubusercontent.com/Laraue/boards-agent/main/install.ps1 | iex
```

Настройка:

1. Выбирает агента — тот, что у вас установлен, или спрашивает, если установлены оба.
2. Открывает Boards в браузере. Проверьте, что код совпадает с кодом в терминале, выберите организацию и нажмите **Разрешить**. Boards создаёт [API-ключ](/ru/documentation/integrations/api-keys) с именем агента и вашего компьютера, например «Claude Code agent (MacBook)», а раннер хранит его в Связке ключей или Диспетчере учётных данных — копировать его никуда не нужно.
3. Спрашивает, в какой папке лежат копии ваших репозиториев — введите путь или выберите папку в Finder или Проводнике — и показывает, какие репозитории нашлись для каждого спейса ([см. ниже](#в-каких-репозиториях-работает-агент)).
4. Спрашивает, [где работать агенту](#где-работает-агент).
5. Спрашивает, что делать с веткой агента, когда он закончит: ничего, запушить или запушить и открыть пул-реквест ([см. ниже](#когда-агент-закончил)).
6. Предлагает запускать раннер в фоне, в том числе после перезагрузки, — тогда ничего не нужно запускать вручную.

Чтобы обновиться, запустите команду установки ещё раз: она заменит laraue-boards-agent и перезапустит его, не задавая вопросы заново. Поменять ответы — `lba setup`. Подробности — в [README](https://github.com/Laraue/boards-agent#readme).

## В каких репозиториях работает агент

Репозитории спейса — это его [ссылки](/ru/documentation/concepts/spaces#описание-и-ссылки): каждая ссылка, URL которой совпадает с git remote репозитория, склонированного на вашем компьютере. Добавьте URL репозитория ссылкой в настройках спейса — и раннер сам найдёт вашу копию: ничего не нужно сопоставлять вручную, а ссылка, добавленная позже, учитывается со следующей передачи. Добавляйте только те репозитории, которые меняют задачи этого спейса: каждый, склонированный на вашем компьютере, участвует в каждом запуске.

У спейса может быть несколько репозиториев — например, бэкенд и веб-приложение. Агент меняет только нужные задаче, на одной и той же ветке в каждом. Описание спейса и его остальные ссылки (документация, дизайн) он получает как контекст, а не как указания.

Задача в спейсе, у которого нет репозитория на вашем компьютере, ждёт — другой ваш компьютер, где он есть.

## Где работает агент

Настройка спрашивает, какой из двух вариантов вам удобнее:

- **Отдельный worktree на задачу** (по умолчанию). Агент работает в своей копии каждого репозитория на ветке с именем задачи, например `agent/WEB-42`. Ваши копии не трогаются, и вы можете тем временем работать в них.
- **Ваши собственные копии, по одной задаче за раз.** Раннер скачивает основную ветку каждого репозитория и переключает вашу копию на новую ветку от неё. Когда агент закончит, ветка остаётся открытой: откройте её в редакторе, запустите приложение и проверяйте как обычно. Копии, которые агент не менял, возвращаются на ветку, где были.

  Чистая копия переключается без вопросов, на какой бы ветке она ни была — например, на ветке прошлой задачи, пока вы её проверяете; её коммиты остаются на той ветке. Спрашивает раннер, в диалоге, только про копию с незакоммиченными изменениями: при переключении они могли бы переехать или столкнуться. **Continue** проверяет снова; ваши незакоммиченные изменения никогда не трогаются, поэтому он спрашивает, пока вы их не закоммитите или не уберёте в stash. **Not now** оставляет задачу ждать и спрашивает снова через 10 минут.

В обоих случаях агент работает с фиксированным списком разрешённых команд и не может пушить.

## Когда агент закончил

- **Уведомления.** Компьютер показывает уведомление от **laraue-boards-agent** с логотипом Laraue, когда агент начинает, когда задача готова к проверке, и если он не справился или запуск отменён. Нажмите на него, чтобы открыть задачу. На Mac первое уведомление может спросить, можно ли laraue-boards-agent присылать уведомления.
- **Ветка.** По умолчанию она остаётся на вашем компьютере — вы смотрите её и пушите сами. Если вы выбрали это в настройке, boards-agent сам пушит её, когда агент закончил, — в каждом репозитории, который агент менял, — и может открыть пул-реквест, если установлен и авторизован [GitHub CLI](https://cli.github.com). Ссылки — в комментарии boards-agent к задаче и в уведомлении. Сам агент никогда не пушит.

## Как попросить изменений

**На своём компьютере: `lba continue`.** Работа агента лежит у вас на компьютере, так что быстрее всего попросить изменений там. В терминале выполните:

```bash
lba continue
```

Откроется собственная сессия агента — тот же разговор, со всем, что он знал, в тех же репозиториях и на ветке задачи. Без ключа задачи берётся задача ветки, на которой вы сейчас, а иначе — та, над которой ваш агент работал последней; команда скажет, какая. Скажите, что не так («кнопка всё ещё синяя», «добавь тест для пустого списка»), смотрите изменения и запускайте приложение сразу: в Boards ничего не двигается и ничего не ждёт раннера. Когда вы выйдете, к задаче добавится один комментарий с новыми коммитами.

Чтобы передать одно изменение, не оставаясь в разговоре, напишите его после команды — кавычки не обязательны. Агент сделает его сам и выведет свой ответ:

```bash
lba continue WEB-42 сделай кнопку красной, как остальные основные кнопки
lba continue WEB-42 выведи JSON дашборда Grafana для новых метрик
```

Сессия есть только на том компьютере, который выполнял задачу. В режиме собственных копий ваши копии сначала переключаются обратно на ветку задачи — спрашивая только про незакоммиченные изменения.

**Из Boards: «Вернуть агенту».** В разделе «Агент» у задачи на проверке **Вернуть агенту** спрашивает, что не так; комментарий добавится, задача вернётся в не начатый статус и снова уйдёт агенту. Он продолжит на той же ветке — в его комментарии будет «continuing … (N commits so far)». Удобно, когда вы не за компьютером.

## Для авторов раннеров

Раннер использует MCP-инструменты: `list_agent_runs` (опрос с `state: Ready`, вашим id из `get_me` в `assigneeIds` и `excludeBlocked: true`), `claim_agent_run` (true — задача ваша, false — пропустить), `finish_agent_run` (`Done` или `Failed` с причиной) `get_issue`, где `latestAgentRun` показывает, не отменён ли запуск, и `get_space` — описание и ссылки спейса. Каждое изменение запуска видно в [истории изменений](/ru/documentation/features/issue-history) задачи вместе с API-ключом, который его сделал.
